# Как управлять сайтом через Pages CMS

Адрес редактора: https://app.pagescms.org (вход через GitHub, репозиторий `settwor.com.pl`).
Всё сохраняется как commit, сайт обновляется через 1–2 минуты. Работает с телефона.

## Разделы редактора
- **News**: статьи. Add an entry → заголовок, краткое описание, дата, обложка, текст. Переключатель «Show on the website» должен быть включён.
- **Biography**: по одной записи на язык. У каждого языка свой адрес и своя страница в Google.
- **Photos**: все фотографии одним списком. Год вкладки берётся из даты фото.
- **Releases**: по одной записи на релиз. Обложка, исполнители, дата, ссылка Spotify.
- **Site**: главная (текст, фото, факты, видео), ссылки справа (Follow, Also on the web), тексты заголовков страниц.

## Новая статья
News → Add an entry. Поля «Custom address» нет: адрес делается из заголовка автоматически.

## Новый язык биографии
Biography → Add an entry → назовите файл кодом языка (например `de`). Заполните:
название языка (Deutsch), код языка (`de`), место в списке, заголовок, описание, текст.
Страница получит адрес `/bio/de/`, кнопку в списке языков, ссылку в подвале и отметку для Google (hreflang).
Адреса `/bio.html`, `/bioRU.html`, `/bioPL.html` не менялись. Испанская и португальская версии: `/bio/es/` и `/bio/pt/`.

## Источники и ссылки (как в Википедии)
В биографиях и статьях внизу есть нумерованный список источников. Он заполняется в полях **Sources** (и **External links** в биографиях):
каждая строка — название, адрес и сайт. В тексте маленькая метка вида [1] — это обычная ссылка на `#ref-1` (двойка — `#ref-2` и т. д.),
она переносит читателя к нужной строке списка. Номер метки = номер строки в списке. Обычные ссылки в тексте ставятся как всегда: `[слово](https://адрес)`.
Ссылка на релиз внутри сайта открывает окно релиза со всеми площадками: `/releases.html#release-имя-файла-релиза` (например `#release-toma-jatada`).

## Дата «Updated» в статье
Ничего не ставится автоматически. Строка «Updated» на странице, дата для Google и `lastmod` в sitemap появляются только если вы сами заполнили поле «Date of the last correction».

## Новое фото
Photos → Add: загрузите файл, поставьте дату, опишите фото. Лучше заранее уменьшить фото до ~2000 px по длинной стороне:
Pages CMS кладёт файл в репозиторий как есть, а тяжёлые файлы замедляют страницу.
Маленькие копии для сетки (быстрее грузятся) делает скрипт на компьютере:
`pip install pillow`, затем `python3 tools/make-thumbs.py` и commit. Без копий сайт просто показывает большие фото.

## Новый релиз
Releases → Add: название, исполнители, дата, обложка, ссылка на Spotify. Список сортируется по дате сам.

## Главная страница и фото на главной
Site → Home page: меняйте фото, тексты, факты, видео, ссылку Spotify. Девять последних фото берутся из раздела Photos, четыре последних релиза — из раздела Releases (число меняется в `index.html`: `limit: 4`).

## Повторные заходы
После первого визита картинки, шрифты и стили хранятся на устройстве (файл `sw.js`), страницы при этом всегда запрашиваются свежими,
а без интернета открываются сохранённые копии. GitHub Pages не позволяет управлять сроками кэша на сервере, поэтому это сделано через `sw.js`.
Чтобы все посетители заново скачали всё, поменяйте `VERSION` в `sw.js`.

## Проверка на своём компьютере
`pip install pyyaml markdown`, затем `python3 tools/serve.py` и откройте http://localhost:8000.
Это упрощённая сборка. Точную проверку даёт вкладка Actions на GitHub.

## Статья SE TU QUER
Сейчас это черновик (скрыт). Откройте запись SE TU QUER в News, вставьте текст статьи в «Text of the article» и включите «Show on the website».
Старого файла `news/SE-TU-QUER-…html` в репозитории больше нет, поэтому до публикации статьи ссылки на неё не работают.

## Один раз после запуска
Search Console → Sitemaps → `sitemap.xml`. URL Inspection → адрес новой страницы → Request indexing.

## Язык биографии выбирается сам
Кнопка «Biography» в меню ведёт на биографию на языке браузера посетителя (русский, польский, испанский, португальский; остальным — английский).
Украинский браузер получает английскую версию, а не русскую. Если человек сам выберет язык в списке языков, сайт запомнит выбор.
Страница `/bio.html` (английская) отправляет посетителей с другим языком браузера на их версию. Остальные языковые страницы никуда не перенаправляют,
поэтому тот, кто пришёл из Google на страницу на своём языке, остаётся на ней. Для нового языка (`de`) ничего настраивать не нужно,
только добавьте блок `de:` в файл `_data/bioui.yml` (подписи «Главное», «Ключевые моменты» и т. д.), иначе эти подписи будут английскими.

## Устройство биографии
- Вверху: блок «Главное» (поле **Key facts**) и «Ключевые моменты» (поле **Key moments**): это самое важное в нескольких строках.
- Ниже вся биография одним длинным текстом, без кнопок и сворачивания. Каждый заголовок второго уровня (`##`) попадает в список «В этой биографии» в левой колонке на широких экранах.
  Ссылки вида `/bio.html#channel-history` ведут к нужному месту.
- Вопросы и ответы (поле **Questions and answers**) видит Google: они выводятся и в тексте страницы, и в разметке FAQPage.
  Google с 2023 года показывает расширенные ответы на вопросы в поиске только для части сайтов, поэтому гарантии «вопросы появятся в выдаче» нет,
  но сама страница из-за них лучше понимается и находится по таким запросам.

## Уведомления о новых статьях
Сайт на GitHub Pages сам ничего отправить не может, поэтому есть два канала:
1. **RSS-лента** `/feed.xml`: обновляется сама из папки `_posts`. Её добавляют в Feedly, Inoreader и другие читалки.
   Ссылка есть на странице новостей, под каждой статьёй и в подвале.
2. **Push-уведомления в браузере (колокольчик)** через OneSignal, бесплатный тариф. Код уже в сайте и выключен, пока не вписан App ID.
   Настройка один раз:
   1. Зарегистрируйтесь на onesignal.com → New App/Website → тип **Web** → **Typical Site**.
   2. Site Name: `SETTWOR`, Site URL: `https://settwor.com.pl` (точно так, без слэша в конце), включите Auto Resubscribe.
   3. Скопируйте **App ID** (длинный код вида `xxxxxxxx-xxxx-...`) и вставьте в `_config.yml` в строку `onesignal_app_id: ""`.
   4. После публикации в углу сайта появится колокольчик. Подпишитесь сами с телефона или компьютера.
   Колокольчик уже включён (App ID вписан в `_config.yml`).
5. **Автоотправка push о новой статье** (файл `.github/workflows/push-news.yml`). Настройка один раз:
   1. В OneSignal: Settings → Keys & IDs → скопируйте **REST API Key**.
   2. В GitHub: репозиторий → Settings → Secrets and variables → Actions → New repository secret.
      Имя `ONESIGNAL_API_KEY`, значение: ключ из шага 1.
   3. Готово. Когда в `_posts` появляется НОВАЯ статья, скрипт ждёт, пока она откроется на сайте (до 15 минут),
      и отправляет всем подписчикам заголовок, описание и ссылку. Правка старой статьи ничего не отправляет.
      Пока секрета нет, скрипт ничего не делает.
   Повторно отправить push вручную: вкладка Actions → Push news → Run workflow → укажите имя файла, например `2026-10-13-title.md` (папку `_posts/` писать не обязательно).
   Можно и без автоматики: OneSignal → Messages → New Push.
   Файл `OneSignalSDKWorker.js` в корне сайта не удаляйте и не меняйте: это единственный воркер сайта (OneSignal плюс кеш из `sw.js`).

## Окно «Хотите получать новости?»
Перед системным вопросом браузера («Разрешить / Блокировать») сайт показывает своё окно (`_includes/push-ask.html`, `js/push-ask.js`, стили в конце `css/main.css`).
Системный вопрос появляется только после нажатия «Yes, notify me»: его можно показать один раз, а «Блокировать» почти никогда не отменяют.
- Окно появляется, когда человек читает страницу 20 секунд и прокрутил её примерно на треть (короткие страницы: 35 секунд). Не показывается вместе с баннером cookie, на страницах privacy/license, тем, кто уже подписан или заблокировал уведомления.
- «Не сейчас» (или Esc, или клик мимо окна): следующий показ через 7 дней, потом через 30 дней, потом больше никогда.
- В окне показан пример уведомления с названием последней статьи. Тексты окна правятся в `_includes/push-ask.html`.
- В панели OneSignal отключите собственное автоокно, чтобы оно не появлялось раньше: Settings → Push & In-App → Permission Prompt Setup → Auto Prompt выключить (или не добавлять Slidedown/Push-prompt в настройках).
