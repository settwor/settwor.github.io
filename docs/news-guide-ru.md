# Как управлять сайтом через Pages CMS

Адрес редактора: https://app.pagescms.org (вход через GitHub, репозиторий `settwor.github.io`).
Всё сохраняется как commit, сайт обновляется через 1–2 минуты. Работает с телефона.

## Разделы редактора
- **News**: статьи. Add an entry → заголовок, краткое описание, дата, обложка, текст. Переключатель «Show on the website» должен быть включён.
- **Biography**: по одной записи на язык. У каждого языка свой адрес и своя страница в Google.
- **Photos**: все фотографии одним списком. Год вкладки берётся из даты фото.
- **Releases**: по одной записи на релиз. Обложка, исполнители, дата, ссылка Spotify.
- **Site**: главная (текст, фото, факты, видео), ссылки справа (Follow, Also on the web), тексты заголовков страниц.

## Новая статья
News → Add an entry. Поля «Custom address» нет: адрес делается из заголовка автоматически.

## Новый язык биографии
Biography → Add an entry → назовите файл кодом языка (например `de`). Заполните:
название языка (Deutsch), код языка (`de`), место в списке, заголовок, описание, текст.
Страница получит адрес `/bio/de/`, кнопку в списке языков, ссылку в подвале и отметку для Google (hreflang).
Адреса `/bio.html`, `/bioRU.html`, `/bioPL.html` не менялись.

## Новое фото
Photos → Add: загрузите файл, поставьте дату, опишите фото. Лучше заранее уменьшить фото до ~2000 px по длинной стороне:
Pages CMS кладёт файл в репозиторий как есть, а тяжёлые файлы замедляют страницу.
Маленькие копии для сетки (быстрее грузятся) делает скрипт на компьютере:
`pip install pillow`, затем `python3 tools/make-thumbs.py` и commit. Без копий сайт просто показывает большие фото.

## Новый релиз
Releases → Add: название, исполнители, дата, обложка, ссылка на Spotify. Список сортируется по дате сам.

## Главная страница и фото на главной
Site → Home page: меняйте фото, тексты, факты, видео, ссылку Spotify. Девять последних фото берутся из раздела Photos.

## Повторные заходы
После первого визита картинки, шрифты и стили хранятся на устройстве (файл `sw.js`), страницы при этом всегда запрашиваются свежими,
а без интернета открываются сохранённые копии. GitHub Pages не позволяет управлять сроками кэша на сервере, поэтому это сделано через `sw.js`.
Чтобы все посетители заново скачали всё, поменяйте `VERSION` в `sw.js`.

## Проверка на своём компьютере
`pip install pyyaml markdown`, затем `python3 tools/serve.py` и откройте http://localhost:8000.
Это упрощённая сборка. Точную проверку даёт вкладка Actions на GitHub.

## Статья SE TU QUER
Сейчас это черновик (скрыт). Откройте запись SE TU QUER в News, вставьте текст статьи в «Text of the article» и включите «Show on the website».
Старого файла `news/SE-TU-QUER-…html` в репозитории больше нет, поэтому до публикации статьи ссылки на неё не работают.

## Один раз после запуска
Search Console → Sitemaps → `sitemap.xml`. URL Inspection → адрес новой страницы → Request indexing.
